# AGENTS.md — `hivemind-rendezvous`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

A store-and-forward dead drop for HiveMind nodes that are never online at the
same time: one node deposits an encrypted `INTERCOM` message addressed to
another node's public key, and the recipient collects it whenever it next
connects. This is not a standalone service — it is a plain hivemind-core node
that happens to hold mail, switched on with a `rendezvous` config flag the
same way [hivemind-presence](https://github.com/JarbasHiveMind/HiveMind-presence)
is enabled. It has no listener, no port, and no credentials of its own; it
serves the `RENDEZVOUS` message type on the socket hivemind-core already
accepts clients on. Part of the [HiveMind](https://github.com/JarbasHiveMind)
ecosystem — a protocol for connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core), which must
route `RENDEZVOUS` to this package's mailbox for it to do anything at all.

## Layout / build / test

- Package module: `hivemind_rendezvous/` (`mailbox.py` serves the three
  `RENDEZVOUS` commands — `deposit`, `collect`, `ack`; `storage.py` is the
  `JsonStorageXDG`-backed mailbox store; `client.py` is a thin helper for
  callers issuing `RENDEZVOUS` requests). Tests live in `test/` (check before
  adding — do not create a second test directory).
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[dev]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest test -q`. Tests point
  `JsonStorageXDG` at a temp directory the test owns — never let a test run
  against the real XDG data dir.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This package has no authentication code of its own, and that is deliberate:
  the mailbox a `collect`/`ack` request operates on is the access key the
  connection already authenticated with, never a caller-supplied identifier.
  Do not add a way to name or target another mailbox — that would reintroduce
  the ownership-proof-and-replay-window problem this design removed (see
  `AUDIT.md`). Admission and flood control are hivemind-core's job; this
  package only bounds `max_pending_per_mailbox` against an authenticated peer
  that misbehaves.
- Only `INTERCOM` may be deposited. Do not widen accepted payload types without
  checking whether the relay would then have a reason to look inside them —
  the whole point of restricting to `INTERCOM` is that it stays opaque.
- Delivery is at-least-once by design: `collect` never deletes, only `ack`
  does. Do not "fix" the apparent duplicate-delivery behavior by deleting on
  read — that trades an occasional detectable duplicate for silently losing
  mail whenever a reply goes missing, which is worse for a peer that is by
  definition unreachable for a resend.
- The store (`storage.py`, `json_database.JsonStorageXDG`) holds everything in
  memory and rewrites the whole file on each change (`AUDIT.md` AUDIT-002).
  That is an accepted trade-off at dead-drop volume, not a bug to silently
  patch around; if volume ever warrants it, the fix is a
  `hivemind-plugin-manager` database backend, not an in-place workaround.
- This is a routing/config flag on hivemind-core, not an independent entry
  point: a change here does nothing in a running hive unless hivemind-core
  actually routes `RENDEZVOUS` to this mailbox. When touching wire-facing
  behavior (command names, payload fields, reply shapes), check that core's
  routing expectations and this package's `client.py` helper stay in sync.
